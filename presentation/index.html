Use Case

What it does

  • Formal end-of-day brief from department heads to the CO at about 2000

Where it breaks down

  • Labor-intensive to compile
  • Prone to human error
  • Disconnected from authoritative systems of record
  • No visibility into trends over time
  • Blind spots across departments
  • Duplicate reporting effort

Edge

Edge-first automation: works 100% offline, once the payload lands

1Shore-side (Enterprise)Aggregates and serializes high-level PMT data (e.g., logistics, parts tracking, personnel updates) into ultra-compressed, text-only payloads such as flat JSON
2The Push (Transit)Sends these tiny payloads over low-bandwidth tactical networks (e.g., C-band/Ku-band or HF secondary lines) only when a connection is established
3The Edge (Shipboard)Ingests the payload into a locally hosted, containerized environment (e.g., Docker on the ship's local network/CANES), with no pipe to the cloud needed

Designed for disconnected, intermittent and limited (DDIL) conditions. Compresses PMT data into lightweight payloads that update ships at the tactical edge.

Looking Ahead

What we learned and where we go next

Lessons learned

  • Data integration is the hard part: plan for it early
  • Connectivity dependence is a real risk: we relied fully on Wi-Fi
  • Token limits shape design: build with them in mind

Next steps

  • Move from synthetic to real data
  • Expand data sources and functionality
  • Package the HTML with Forge to meet cybersecurity requirements
  • Build a bidirectional data pipeline between environments
Conclusion
